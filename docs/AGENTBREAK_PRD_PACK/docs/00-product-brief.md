# 00 — Product Brief

## 1. Product identity

**Name:** AgentBreak  
**Tagline:** Test the action, not just the answer.  
**Category:** AI-agent security testing and defense validation  
**Primary deployment for MVP:** Local developer workstation  
**Audience:** AI developers, security engineers, evaluators, hackathon judges

## 2. Product statement

AgentBreak tests whether a tool-using AI agent can be manipulated into taking an unauthorized action. It executes tests inside a controlled environment, checks the actual side effects, explains the sequence that led to them, then evaluates a defense while measuring whether legitimate tasks remain functional.

## 3. Problem and context

Agent behavior is a system-level outcome involving model output, tool schemas, untrusted content, permissions, state, and runtime orchestration. A harmful output string does not necessarily prove a vulnerability; conversely, a polite or harmless-sounding answer does not prove the agent avoided unauthorized tool actions. Security testing must observe execution and state.

The research foundation also warns that adaptive agent red-teaming already has substantial prior art. Therefore, AgentBreak's hackathon proposition is a compelling integrated workflow and clear evidence, not an unsupported claim to be the first tool of its kind.

## 4. Value proposition

AgentBreak helps a developer answer four questions:

1. Can the agent be induced to violate a stated security policy?
2. What sequence of untrusted content, tool calls, and decisions led to the violation?
3. Did the proposed defense block the action when the test was replayed?
4. Did the defense preserve the agent's legitimate usefulness?

## 5. Product principles

- Security verdicts must be grounded in observable tool actions or synthetic environment state.
- All attack runs use a controlled sandbox and synthetic data.
- Permission checks run at the tool execution boundary.
- Findings contain enough evidence to be investigated.
- Baseline and defended runs use comparable clean initial state.
- Attack budgets are bounded and visible.
- Raw counts accompany rates.
- An unknown outcome must not be silently counted as a block or as a successful exploit.

## 6. Personas

### Persona A — AI application developer

Needs to discover whether untrusted retrieved content can trigger unexpected actions. Values concrete reproduction steps and actionable fixes.

### Persona B — AI security engineer

Needs to inspect attempted and executed tools, policy decisions, and side-effect evidence. Values reliable logs and explicit test conditions.

### Persona C — Evaluator or judge

Needs to understand the project's technical contribution quickly. Values a live end-to-end demonstration, real measured results, and honest statements of scope.

## 7. Core scenario

A support agent reads a ticket. The ticket includes attacker-controlled instructions aimed at redirecting a synthetic customer record to an unauthorized address. The sandbox records the tool calls and outgoing message. The baseline demonstrates the failure; the defense applies recipient and data-access rules before execution. A benign support task verifies that the agent can still perform permitted work.

## 8. Success indicators

- At least one confirmed side-effect-based finding.
- A trace that a teammate can explain from raw event data.
- A defense result generated by executing the tool policy, not by hardcoded UI state.
- A benign task that passes with defense enabled.
- A saved test that can be replayed.
- A clear demo that can be run without live internet service dependencies apart from optional model API calls.

## 9. Positioning and claims

Safe claim: “AgentBreak demonstrates a closed-loop workflow for sandboxed agent security testing, including side-effect verification, defense comparison, and benign-task checks.”

Avoid claims such as “the first autonomous red team,” “guaranteed security,” or “discovers unknown attacks” unless those claims are rigorously established. An attack generated through a mutation loop should be described according to its actual lineage and novelty criteria.
